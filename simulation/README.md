# Симулятор Банков QRPayHub

Независимый модуль для демонстрации и отладки двухфазных транзакций между банками.

## 🎯 Назначение

Симулятор предоставляет веб-интерфейс для наглядной демонстрации работы протокола двухфазного коммита (2PC) в QRPayHub:

- **Банк Отправителя** - интерфейс для инициации платежей с live-логами
- **Банк Получателя** - мониторинг счета продавца в реальном времени  
- **Mock API** - эмуляция ответов реальных банков

## 🚀 Быстрый старт

### 1. Запуск с симулятором

```bash
# Способ 1: Через скрипт
python run_with_simulator.py

# Способ 2: Через переменную окружения
ENABLE_BANK_SIMULATOR=true uvicorn app.main:app --reload

# Способ 3: Установка переменной в Windows
set ENABLE_BANK_SIMULATOR=true
uvicorn app.main:app --reload
```

### 2. Подготовка данных

```bash
# Инициализация базы данных с тестовыми данными
python init_db.py --reset
```

### 3. Открытие симулятора

Перейдите по адресу: http://localhost:8000/simulation

## 📱 Использование

### Сценарий 1: Тест двухфазной транзакции

1. **Создание QR-кода**:
   - Откройте админ панель: http://localhost:8000/admin
   - Создайте QR-код для тестового платежа
   - Скопируйте ссылку из QR-кода

2. **Запуск симулятора отправителя**:
   - Замените `/pay?token=` на `/simulation/scan?token=` в ссылке
   - Откройте новую ссылку в браузере
   - Вы увидите интерфейс банка-отправителя

3. **Открытие симулятора получателя**:
   - В новой вкладке откройте http://localhost:8000/simulation
   - Нажмите на любой банк в таблице -> "Счет"
   - Откроется интерфейс мониторинга баланса

4. **Выполнение платежа**:
   - В интерфейсе отправителя нажмите "Оплатить"
   - Наблюдайте за логами двухфазной транзакции в реальном времени
   - В интерфейсе получателя увидите обновление баланса

### Сценарий 2: Настройка Mock API

1. **Включение симуляции**:
   - Откройте http://localhost:8000/simulation
   - Нажмите "Включить симуляцию"
   - Все банки будут настроены на Mock API

2. **Тестирование**:
   - Mock API автоматически отвечает на запросы prepare/commit/abort
   - Можно добавить параметры `?simulate_delay=true` или `?simulate_error=true`

## 🔌 API эндпоинты

### Интерфейсы
- `GET /simulation` - Главная страница симулятора
- `GET /simulation/scan?token=XXX` - Симулятор банка-отправителя
- `GET /simulation/receiver-account/{merchant_id}` - Симулятор банка-получателя

### Mock API банков
- `POST /simulation/bank-api/prepare` - Эмуляция prepare запроса
- `POST /simulation/bank-api/commit` - Эмуляция commit запроса  
- `POST /simulation/bank-api/abort` - Эмуляция abort запроса

### Служебные API
- `GET /simulation/api/payment/{token}/logs` - Получение логов транзакции
- `GET /simulation/api/merchant/{id}/balance` - Получение баланса продавца
- `POST /simulation/api/configure-mock-banks` - Настройка банков на Mock API

## ⚙️ Конфигурация

### Переменные окружения

- `ENABLE_BANK_SIMULATOR=true` - Включает симулятор (по умолчанию false)

### Интеграция с основным приложением

Симулятор интегрируется через условный импорт в `app/main.py`:

```python
ENABLE_BANK_SIMULATOR = os.getenv("ENABLE_BANK_SIMULATOR", "false").lower() == "true"
if ENABLE_BANK_SIMULATOR:
    from simulation.simulation_router import router as simulation_router
    app.include_router(simulation_router)
```

## 🔧 Отладка

### Логи транзакций

Все двухфазные операции записываются в таблицу `TwoPhaseOperation`:
- Время выполнения каждой фазы
- Запросы и ответы банков
- Ошибки и повторные попытки

### Мониторинг в реальном времени

Симулятор опрашивает API каждую секунду для получения актуальных логов:
```javascript
// В sender_bank.html
setInterval(() => {
    fetch(`/api/v1/payment/${paymentUUID}/logs`)
        .then(response => response.json())
        .then(data => updateLogsFromAPI(data));
}, 1000);
```

## 🚀 Продакшн

### Отключение симулятора

Для продакшна просто не устанавливайте переменную `ENABLE_BANK_SIMULATOR` или установите её в `false`.

Симулятор полностью независим и не влияет на основное приложение:
- Нет импортов в основном коде
- Нет зависимостей в requirements.txt
- Можно удалить папку `simulation/` целиком

### Удаление симулятора

```bash
# Удаление всех файлов симулятора
rm -rf simulation/
rm run_with_simulator.py

# Очистка от симулятора в main.py (опционально)
# Удалите строки с ENABLE_BANK_SIMULATOR
```

## 📝 Примеры использования

3. Проверьте записи в таблице `TwoPhaseOperation`

2. Создайте множественные транзакции
3. Мониторьте производительность через симулятор

2. Убедитесь, что база данных инициализирована
