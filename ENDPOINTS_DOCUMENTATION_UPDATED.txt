## 1. ПЛАТЕЖНЫЕ ЭНДПОИНТЫ (/payment)

### GET /api/v1/payment/payment-info
**Описание:** Получение информации о платеже по токену
**Функция:** Возвращает детали платежа, включая сумму, получателя, статус
**Параметры:** 
- `token` (query, string) - токен платежа
**Ответ:**
```json
{
  "payment_token": "string",
  "amount": 1000.00,
  "currency": "KZT",
  "merchant_name": "string",
  "status": "pending|paid|expired|cancelled",
  "created_at": "2024-01-01T00:00:00Z",
  "expires_at": "2024-01-01T01:00:00Z"
}
```

### POST /api/v1/payment/payment-status
**Описание:** Обновление статуса платежа (webhook от банка)
**Функция:** Обрабатывает уведомления от банков о статусе платежа
**Тело запроса:**
```json
{
  "payment_token": "string",
  "status": "success|failed|cancelled",
  "transaction_id": "string",
  "amount": 1000.00,
  "signature": "string",
  "timestamp": "2024-01-01T00:00:00Z"
}
```
**Ответ:**
```json
{
  "success": true,
  "message": "Status updated successfully"
}
```

### POST /api/v1/payment/two-phase-payment
**Описание:** Двухфазная обработка платежа
**Функция:** Выполняет платеж в две фазы: подготовка и подтверждение с идемпотентностью
**Тело запроса:**
```json
{
  "token": "qr_abc123def456",
  "amount": 1000.00,
  "currency": "KGS",
  "payer_phone": "+996700123456",
  "sender_account": "1234567890",
  "payment_reference": "PAY-2024-001",
  "idempotency_key": "idemp_abc123def456_20240101_120000"
}
```
**Ответ:**
```json
{
  "success": true,
  "transaction_id": "2PC_qr_abc123def456_1704110400",
  "status": "completed",
  "message": "Two-phase transaction completed successfully",
  "amount": 1000.00,
  "currency": "KGS",
  "requires_manual_intervention": false
}
```
**Особенности:**
- **Идемпотентность**: Повторные запросы с тем же `idempotency_key` возвращают кэшированный результат
- **Валидация**: Проверка суммы, валюты и формата токена
- **Транзакционная изоляция**: Атомарные операции с защитой от race conditions
- **Мониторинг**: Полное логирование и отслеживание всех операций

### GET /api/v1/payment/{payment_token}/logs
**Описание:** Получение логов платежа
**Функция:** Возвращает историю операций по конкретному платежу
**Параметры:** 
- `payment_token` (path, string) - токен платежа
**Ответ:**
```json
{
  "logs": [
    {
      "id": 1,
      "action": "payment_created",
      "timestamp": "2024-01-01T00:00:00Z",
      "details": "string"
    }
  ]
}
```

## 3. АДМИН ЭНДПОИНТЫ (/admin)

### ЕДИНЫЙ СТАТИСТИЧЕСКИЙ ЭНДПОИНТ (/admin/statistics)

#### GET /api/v1/admin/statistics/statistics
**Описание:** Единый эндпоинт для получения всех типов статистики
**Функция:** Возвращает различные типы статистики в зависимости от параметров
**Параметры:**
- `metric` (query, required) - тип метрики:
  - `dashboard` - статистика для дашборда
  - `merchant_quick` - быстрая статистика продавца
  - `merchants_overview` - обзор всех продавцов
  - `admin_summary` - сводка для админа
  - `system` - системная статистика
  - `dashboard_full` - полная сводка дашборда
  - `audit_summary` - сводка аудита
  - `top_merchants` - топ продавцов
  - `monitoring_summary` - сводка мониторинга
  - `bank_stats` - статистика по банкам
- `period` (query, default: "7d") - период:
  - `1h`, `24h`, `7d`, `30d`, `month`, `year`
- `merchant_id` (query) - ID продавца для merchant_quick

## ОБЩАЯ ИНФОРМАЦИЯ

**Всего эндпоинтов после рефакторинга:** ~180 (сокращено с ~200+)
**Основные изменения:**
- ✅ Объединены все алерты в `/admin/alerts`
- ✅ Создан единый эндпоинт статистики `/admin/statistics`
- ✅ Удалены устаревшие модули `/mbank`, `/qr`, `/alerts`
- ✅ Удалены тестовые эндпоинты из продакшена
- ✅ Улучшена архитектура и уменьшена избыточность

**Ключевые возможности системы:**
- **Торговые точки (филиалы)**: Создание и управление торговыми точками с названием, адресом и описанием
- **Статичные QR-коды**: Генерация QR-кодов для торговых точек без фиксированной суммы
- **Динамические QR-коды**: Создание QR-кодов с конкретной суммой для разовых платежей
- **Двухфазные платежи**: Поддержка современной схемы платежей с подготовкой и подтверждением
- **Мониторинг и алерты**: Полная система мониторинга с уведомлениями
- **Детальная статистика**: Статистика по продавцам, торговым точкам, банкам и системе в целом

**Аутентификация:** 
- Большинство эндпоинтов требуют аутентификации через токены
- Админские эндпоинты требуют админской аутентификации

**Валидация:** 
- Все входные данные валидируются через Pydantic модели
- Подробные сообщения об ошибках

**Логирование:** 
- Все операции логируются для аудита
- Отдельные логи для платежей, админских действий, ошибок

**Безопасность:**
- HMAC подписи для webhook'ов
- Rate limiting для всех эндпоинтов
- Валидация QR-кодов на безопасность

**Документация:** 
- Все эндпоинты имеют подробную документацию
- Примеры запросов и ответов
- Описание всех полей и параметров
